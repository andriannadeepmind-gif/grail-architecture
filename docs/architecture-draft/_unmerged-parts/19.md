### 19.3 Διαδικασία αναθεώρησης

```mermaid
stateDiagram-v2
    [*] --> PROPOSED: amendment proposal (via can-adopt surface)
    PROPOSED --> COURT_REVIEW: admissible (provenance, diff, rationale)
    COURT_REVIEW --> REJECTED: refuted / non-LLM oracle red
    COURT_REVIEW --> CREATOR_SIGNATURE: verdict + dissents recorded
    CREATOR_SIGNATURE --> REJECTED: creator declines
    CREATOR_SIGNATURE --> COMPILE_ROUNDTRIP: Owner-Root-delegated signature
    COMPILE_ROUNDTRIP --> REJECTED: compiled != enforced
    COMPILE_ROUNDTRIP --> COOLING: Tier 0 only
    COMPILE_ROUNDTRIP --> EFFECTIVE: Tier 1
    COOLING --> DST_REPLAY: T_cool elapsed
    DST_REPLAY --> REJECTED: any KT red
    DST_REPLAY --> EFFECTIVE: all KT green
    EFFECTIVE --> [*]: new constitution version in ledger; all active Control Records re-evaluated
    REJECTED --> [*]
```

Κάθε έκδοση του συντάγματος είναι γεγονός στο ledger με JCS-hash (ταυτότητα κατά SC-LOAD). Μη έγκυρη αναθεώρηση απορρίπτεται και η τρέχουσα μένει σε ισχύ.

### 19.5 Κανόνες του μητρώου

1. **Κάθε invariant έχει σημείο επιβολής, formal artifact ή εμπειρικό test, και έδρα.** Όπου η στήλη formal είναι «—», η ιδιότητα είναι εμπειρική και καλύπτεται από KT/VT με μη-LLM oracle ([0093] ii).
2. **Τα υπάρχοντα invariants του prototype (MEM-\*, T-\*, R-\*, AC-R:\*, SC-Art\*, KL-\*, TB-\*, PO-\*) δεν επαναδιατυπώνονται.** Η τελευταία στήλη δείχνει ποια επεκτείνει κάθε GRAIL invariant· σε σύγκρουση υπερισχύει η υπάρχουσα έδρα μέχρι να αναθεωρηθεί.
3. **Τα κατώφλια (ε, θ, Δ, T_cool, bounds) είναι Tier-1 δεδομένα**, όχι σταθερές κώδικα. Ορίζονται και υπογράφονται πριν από κάθε μέτρηση (προκαταχώριση, §24).

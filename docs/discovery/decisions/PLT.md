## DEC-PLT-01 · Ποια είναι η μία έδρα του model: το git (κείμενο + JSON) ή η βάση του SysON;

**Πρόταση:** (A) Έδρα της εγκεκριμένης κατάστασης είναι το git: .sysml κείμενο για review/parse/diff και byte-exact SysON JSON για πιστή επαναφορά, σε υπογεγραμμένο tag ανά δόση. Το SysON + mcp-syson είναι η έδρα εργασίας. Ροή μόνο SysON → export → πύλη → «εγκρίνω» → commit. Αυτό απαιτεί ρητή τροποποίηση ή ερμηνεία του «όχι ως κείμενο» της CLAUDE.md και αναθεώρηση της ADR-0002.

- **A: git = έδρα εγκεκριμένης κατάστασης (κείμενο + JSON), SysON = έδρα εργασίας** — υπέρ: Ιστορικό, υπογραφές και review που το SysON δεν έχει· ζωντανά εργαλεία για agents· η επαναφορά με το JSON μπορεί να διατηρεί IDs. · κατά: Δύο αποθήκες προς συμφιλίωση· αν η επαναφόρτωση του JSON διατηρεί IDs και διαγράμματα δεν ξέρω· αποκλίνει από τη διατύπωση της CLAUDE.md.
- **B: βάση SysON = έδρα, git = ιστορικό στιγμιοτύπων (κατά γράμμα η CLAUDE.md και το export-model.ps1)** — υπέρ: Συμφωνεί με το ισχύον συμβόλαιο και το υπάρχον script· καμία ασάφεια για το πού γίνεται η επεξεργασία. · κατά: Η έδρα δεν έχει VC ούτε authentication· η εγκεκριμένη κατάσταση δεν ξεχωρίζει από την εργασία σε εξέλιξη· η ανάκτηση εξαρτάται από τη βάση.
- **C: text-first, το SysON μόνο viewer** — υπέρ: Καθαρή μία έδρα· ροή όπως στον κώδικα (SEI 2026). · κατά: Χάνονται τα ζωντανά εργαλεία του mcp-syson ή χρειάζεται re-import κάθε φορά, με απώλεια IDs· το ώριμο language toolchain (Syside) είναι επί πληρωμή.
- **D: Flexo MMS (SysML v2 API με ιστορικό) = έδρα** — υπέρ: Commits/branches/merge/diff μέσα στο πρότυπο API. · κατά: Beta· RDF/Fuseki stack· καμία ενσωμάτωση με SysON· MCP με 10 commits.

**Γιατί:** Κανένα υπαρκτό σύστημα δεν κυριαρχεί. Η A κρατά την αρχή της ADR-0002 (ιστορικό, έγκριση) χωρίς να χάνει τη ζωντανή πλατφόρμα της CLAUDE.md. Τη διατύπωση όμως μόνο ο δημιουργός μπορεί να την αλλάξει.

**Επηρεάζει:** ADR-0002, REQ-MDL-001, CMP-MDL-01, ICD-32, ADR-0028

## DEC-PLT-02 · Πώς αντικαθίσταται η ADR-0001 και πώς γίνεται το crosswalk προς το LAWMAX-Ω;

**Πρόταση:** Νέα ADR που αντικαθιστά την ADR-0001: έδρα το repo grail-architecture. Το crosswalk γίνεται με read-only pinned αναφορές (repo, commit, path) στα metadata του model, χωρίς εγγραφές στο άλλο repo. Οι GP-n αντιστοιχίζονται στις δόσεις της CLAUDE.md με απόφαση του δημιουργού.

- **Διατήρηση της ADR-0001 (deployment/grail/)** — υπέρ: Συνύπαρξη με τις έδρες του LAWMAX-Ω. · κατά: Παραβιάζει την CLAUDE.md· κατά το πρόχειρο, το branch εκεί αποκλίνει από το origin/main κατά 420 commits (ανεπαλήθευτο από εδώ).
- **git submodule του άλλου repo** — υπέρ: Pinned αναφορά σε επίπεδο git. · κατά: Απαιτεί πρόσβαση σε ιδιωτικό repo και φέρνει περιεχόμενο άλλου έργου στο working tree.
- **Καθόλου crosswalk** — υπέρ: Απλότητα. · κατά: Χάνεται το δόγμα «επέκταση υπαρχουσών εδρών»· κίνδυνος διπλών εδρών.

**Γιατί:** Το συμβόλαιο του δημιουργού έχει ήδη αλλάξει την τοποθεσία· χρειάζεται ρητή τυπική αντικατάσταση.

**Επηρεάζει:** ADR-0001, ADR-0032

## DEC-PLT-03 · Ποιος είναι ο μηχανικός oracle της πύλης του model;

**Πρόταση:** Σύντομο συγκριτικό πείραμα στο ίδιο exported corpus: OMG pilot (αν τρέχει headless μέσω Jupyter kernel ή Xtext standalone), MontiCore CLI, sysml-v2-lsp και, αν δοθεί άδεια ή trial, Syside Modeler CLI. Κύριος oracle γίνεται ο pilot αν αποδειχθεί headless· με N-version ≥2. Αλλιώς ο δημιουργός αποφασίζει για άδεια Syside.

- **Syside Modeler CLI ως κύριος** — υπέρ: Headless CLI για CI, on-prem/air-gapped, τεκμηριωμένη χρήση στην πρακτική SEI 2026. · κατά: Επί πληρωμή· η πύλη εξαρτάται από vendor (αρχή 5).
- **OMG pilot ως κύριος, χωρίς πείραμα** — υπέρ: Reference, EPL, μηδενικό κόστος. · κατά: Η headless χρήση για CI δεν τεκμηριώνεται· κίνδυνος χρόνου στήσιμου.
- **Μόνο η validation του SysON** — υπέρ: Μηδενικό στήσιμο. · κατά: «experimental… not recommended for production»· δεν είναι ανεξάρτητη.

**Γιατί:** Ανεξαρτησία και δόγμα N-version, χωρίς να δεσμευτεί η σχεδίαση σε oracle που δεν έχει δείξει ότι τρέχει σε CI.

**Επηρεάζει:** CMP-MDL-01, REQ-MDL-002, REQ-MDL-001

## DEC-PLT-04 · Επαναστόχευση του EXP-17;

**Πρόταση:** Ναι: fidelity SysON↔git. (1) insert/upload με read-back και καταμέτρηση· (2) export μέσω του τεκμηριωμένου GET, parse με τον oracle του DEC-PLT-03, re-import σε scratch project και δομικό diff κατά qualified names· (3) δοκιμή επαναφοράς από το JSON (IDs, representations)· (4) κάλυψη των κατασκευών του GRAIL (requirement def/usage, satisfy, verify, derivation, constraint/assert, interface/port, allocation, metadata). Το εμπορικό round-trip μένει προαιρετικό στάδιο viewer.

- **Διατήρηση του αρχικού (εμπορικό round-trip)** — υπέρ: Ελέγχει πολυ-vendor διαλειτουργικότητα. · κατά: Άδειες· όριο CE 500 στοιχείων· το Capella bridge είναι SysML v1.4· δεν ελέγχει τον δρόμο της έδρας.
- **Κατάργηση του EXP-17** — υπέρ: Εξοικονόμηση. · κατά: Η fidelity της έδρας μένει ανεπαλήθευτη, ενώ είναι κριτήριο εξόδου του GP-0.

**Γιατί:** Ελέγχει την πραγματική έδρα χωρίς κόστος αδειών· η διαλειτουργικότητα διατηρείται ως προαιρετικό στάδιο.

**Επηρεάζει:** EXP-17, REQ-MDL-001, ADR-0002

## DEC-PLT-05 · Pin γλώσσας και πολιτική αναβάθμισης του SysON;

**Πρόταση:** Pin σε SysML 2.0 / KerML 1.0 formal. Παραμονή στο τοπικό SysON v2026.7.0 (επιβεβαιωμένο με docker inspect· πιστοποιημένο με mcp-syson από την 0.8.4) με υποχρεωτικό read-back. Αναβάθμιση μόνο αφού το mcp-syson πιστοποιηθεί σε νεότερη έκδοση.

- **Αναβάθμιση τώρα σε v2026.9.0 (09-09-2026)** — υπέρ: Derivation edges (#original/#derive) και άλλες βελτιώσεις. · κατά: Χωρίς πιστοποίηση με mcp-syson· δεν φέρνει την αναφορά μερικής εισαγωγής, που είναι στην 2026.11.0 (υπό ανάπτυξη).
- **Pin σε 2.1/1.1 Beta** — υπέρ: Νεότερο metamodel, ευθυγραμμισμένο με τον pilot 0.61.0. · κατά: Beta· οι libraries του SysON είναι στη βάση 2025-07.

**Γιατί:** Σταθερότητα, ανιχνευσιμότητα απώλειας και ταύτιση με την πιστοποιημένη τοπολογία.

**Επηρεάζει:** CMP-MDL-01, ADR-0002

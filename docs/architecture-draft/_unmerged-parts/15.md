## 15. Interface Control Documents

Έδρα: pkg `Interfaces` του canonical model· machine contracts στο `contracts/` (§16). Κάθε ICD είναι **συμβόλαιο πριν από υλοποίηση** (αρχή 3): ένα component εξαρτάται μόνο από ICDs, ποτέ από υλοποίηση άλλου component (κανόνας §6.1).

### 15.1 Υποχρεωτικό περιεχόμενο κάθε ICD

| Πεδίο | Περιεχόμενο |
|---|---|
| Provider / consumers | Ένας provider-ιδιοκτήτης του συμβολαίου (όπου αναφέρονται περισσότεροι, είναι *ομάδες λειτουργιών* του ίδιου συμβολαίου με έναν ιδιοκτήτη ανά ομάδα)· κατάλογος consumers |
| Binding | gRPC (`contracts/proto/…`), OpenAPI 3.1, AsyncAPI 3.0, WIT (Wasm component model), OTLP ή SysML v2 API |
| Operations | Ονόματα, προϋποθέσεις, αποτελέσματα, idempotency |
| Data | Αναφορές στα JSON Schemas του `contracts/schemas/` (η **μία** έδρα σχημάτων) |
| Semantics / QoS | Συνέπεια (linearizable / causal / eventual), ordering, latency class, durability (Persistence Receipt) |
| Errors | Τυποποιημένα σφάλματα `ERR_INVALID`, `ERR_UNAUTHORIZED_CAPABILITY`, `ERR_CONFLICT`, `ERR_UNAVAILABLE`, `ERR_INTEGRITY`· και το **`Unknown`** ως αποτέλεσμα επιτυχίας, όχι σφάλμα (INV-C04, INV-EXIT-CODES)· το `CONTROL_RESTRICTED` πάντα ορατό (INV-C02) |
| Security | mTLS, capability token (INV-S02), υπογραφή πράξεων με delegated κλειδί (INV-I04), confidentiality domain (INV-L03) |
| Versioning | semver· additive-only εντός major· breaking change = νέο major + ADR + VT-902 |
| Conformance | Σουίτα `VT-0nn` (1:1 με το ICD-nn) με vectors στο `deployment/verify/` (υπάρχουσα έδρα N-version vectors)· κάθε υλοποίηση, σε οποιαδήποτε γλώσσα, επιστρέφει την ετυμηγορία του INDEX για κάθε vector (VEC-1/VEC-2) |
| Υπάρχουσα έδρα | Η as-built έδρα που το ICD τυποποιεί (§6.4) |

**Kernel Contract Freeze.** Τα ICD-01…ICD-12 παγώνουν στην έξοδο του GP-1, ευθυγραμμισμένα με το FF4 kernel freeze του Ω+ plan. Μετά από αυτό, αλλαγή είναι συνταγματική πράξη (INV-C05, ADR-0009) — έτσι υλοποιείται ο στόχος T8 «χωρίς επανασχεδιασμό πυρήνα».

### 15.4 Κανόνες σύνθεσης

1. **Κανένα ICD δεν εκθέτει υλοποίηση.** Π.χ. το ICD-17 δεν εκθέτει «SPARQL endpoint του Oxigraph»· εκθέτει as-of σημασιολογία που σήμερα υλοποιεί το `version-graph`.
2. **Κάθε ICD έχει έναν ιδιοκτήτη ανά ομάδα λειτουργιών.** Όπου ένα ICD έχει ομάδες (ICD-13, ICD-15, ICD-26, ICD-29, ICD-30), οι ομάδες απαριθμούνται ρητά. Δεν υπάρχουν δύο providers για την ίδια λειτουργία.
3. **Τα kernel ICDs δεν γνωρίζουν τίποτα γνωσιακό** (ADR-0004): αντικείμενά τους είναι μόνο γεγονότα, content addresses, κλειδιά, capabilities, controls, κατηγορήματα, χρόνος, χώρος και πόροι.
4. **Κάθε ICD είναι extension point.** Νέα υλοποίηση περνά από conformance (VT-0nn) και ORP· αυτός είναι ο μηχανισμός απορρόφησης του §28.
